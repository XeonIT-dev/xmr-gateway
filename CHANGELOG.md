# Changelog

All notable changes to `xmr-gateway` are documented in this file.

## [0.1.5] - 2026-11-22

### Added
- **Multi-Arch GHCR Container Publishing (`.github/workflows/release.yml`, `deploy/docker/docker-compose.yml`, `deploy/podman/quadlet/*.container`):** Added automated `linux/amd64` + `linux/arm64` image publishing to GitHub Container Registry (`ghcr.io/xeonit-dev/xmr-gateway` and `ghcr.io/xeonit-dev/xmr-gateway-wallet-rpc`) tagged with `<tag>`, `<version>`, and `latest` (with `dry_run: true` build-only verification), and updated Compose & Quadlet manifests to pull prebuilt GHCR images by default while preserving local build support.
- **Dynamic Daemon Restore-Height Resolution (`admin/lib/common.sh`, `admin/wallet.sh`, `start.sh`):** When neither `--restore-height` nor `WALLET_RESTORE_HEIGHT` is explicitly set, wallet creation now queries `MONERO_DAEMON_RPC_URL` / `MONERO_REMOTE_NODE` (`/get_height` with JSON-RPC `get_block_count` fallback) and derives `max(0, height - 1000)` (with updated safe offline fallbacks `mainnet=3500000`, `stagenet=2000000`, `testnet=2900000`).

### Fixed
- **Scanner Sync-Lag Guard Against False `MEMPOOL -> REORGED` (`src/services/scanner.rs`, `src/config.rs`):** When a `MEMPOOL` transaction leaves `pool` before appearing in `in` (without `double_spend_seen`), the scanner now checks `wallet_height` vs. daemon `get_info` (`MONERO_DAEMON_RPC_URL` or read-only `MONERO_REMOTE_NODE` fallback) and defers the `REORGED` transition with a `WARN` log while `wallet_height < daemon_height` or `synchronized == false`, preserving strict fail-closed `REORGED` detection when synced (`lag == 0`) or on explicit double-spends.
- **Exact `refresh-from-block-height` Persistence in `wallet create-view-only` & `create-hot` (`admin/wallet.sh`, `start.sh`):** Cleaned up `stdin` piping for `monero-wallet-cli --generate-from-view-key` (`address` + `view_key` when `--restore-height` is passed) and explicitly pinned `set refresh-from-block-height <height>` inside `.keys` for both `create-view-only` and `create-hot` so `--generate-new-wallet` and `--generate-from-view-key` reliably persist the resolved height.
- **Container Deployment Guides (`DEPLOY_EN.md`, `DEPLOY_RU.md`, `README.md`, `README_RU.md`):** Replaced `podman run` in Docker Compose instructions with native `docker compose run`, added GHCR `pull && up -d` quick-start paths, replaced stale hardcoded restore heights with `<CURRENT_HEIGHT>` guidance (`curl -s http://<node>/get_height`), and added post-start `lag=0` sync verification reminders.

## [0.1.4] - 2026-11-21

### Fixed
- **Strict `sweep_all` Array Length Validation (`src/services/scanner.rs`, `src/rpc/types.rs`):** Fails closed when `sweep_all` returns a non-empty `tx_hash_list` with missing or mismatched `amount_list` / `fee_list` lengths, retaining the attempt in `PREPARED` and recording a diagnostic sweep error for outgoing-transfer reconciliation instead of persisting zero-piconero `SWEPT` totals.
- **Hardened `db backup` Against Symlink & Directory Permission Clobbering (`admin/db.sh`):** Never invokes `chmod 700` on an already-existing destination directory (preserving `/tmp`'s `1777` or existing backup folder permissions), isolates backups targeting world-writable directories inside a `0700` `mkdtemp` subdirectory, rejects pre-existing symlinks, adds a random `secrets.token_hex(6)` filename suffix, and opens the target file exclusively with `O_CREAT | O_EXCL | O_NOFOLLOW | O_RDWR` (`0600`) and `os.fchmod`.
- **Batched `get_outgoing_transfers` in `reconcile_in_flight_sweeps` (`src/services/scanner.rs`):** Groups monitored sweep attempt subaddresses by `account_index` and queries `get_outgoing_transfers` in chunks of `SCANNER_SUBADDRESS_BATCH_SIZE` (instead of $O(N)$ individual RPC calls per attempt), while bounding default `CONFIRMED` sweep reorg polling to a 30-day window when `SUBADDRESS_MONITOR_DAYS=0`.
- **Non-Blocking Static `DEFAULT_WEBHOOK_URL` Validation on Invoice Creation (`src/api/handlers.rs`):** Uses synchronous `validate_webhook_url_static` for operator-configured `DEFAULT_WEBHOOK_URL` when a request omits `callback_url` so transient external DNS outages never fail `POST /api/v1/invoices` with `400 Bad Request` (while preserving live DNS validation for client-supplied `callback_url` and connection-time DNS/IP pinning in `WebhookDispatcher`).
- **Fail-Closed `TransferEntry::subaddress_amounts` & Multi-Batch Chain Height Consistency (`src/rpc/types.rs`, `src/services/scanner.rs`):** Rejects malformed `get_transfers` entries where `!amounts.is_empty() && amounts.len() != subaddr_indices.len()`, replaces `saturating_add` with checked addition returning `AmountOverflow`, and verifies `get_height` consistency before and after multi-batch `get_transfers` loops to prevent split-height evaluation across chunks.
- **Deprecated IPv6 Site-Local (`fec0::/10`) SSRF Blocking (`src/security/url_policy.rs`):** Blocks `fec0::/10` (RFC 3879 site-local) across static URL literals and DNS-resolved webhook addresses.
- **SQLite Query Plan & Index Optimizations (`src/db/repository.rs`, `migrations/20260304000000_sweep_attempts_invoice_status_idx.sql`):** Rewrote `list_monitored_invoices(Some(cutoff))` using `UNION` so SQLite uses `idx_invoices_status` and a range scan on `idx_invoices_created_at` instead of a full index scan, and added composite index `idx_sweep_attempts_invoice_status(invoice_id, status)`.
- **Tarball Installer Script Permissions (`scripts/install.sh`):** Explicitly enforces `0755` permissions on `$PREFIX/admin/*.sh` and `$PREFIX/deploy/systemd/render-wallet-rpc-conf.sh` under `umask 077`, and installs `/usr/share/xmr-gateway/scripts/render-wallet-rpc-conf.sh` during system tarball installations.

## [0.1.3] - 2026-11-21

### Fixed
- **Systemd `ExecStartPre` External POSIX Helper (`deploy/systemd/render-wallet-rpc-conf.sh`, `monero-wallet-rpc.service`):** Extracted inline `ExecStartPre=/bin/sh -ec '...'` into a dedicated `0755` POSIX script installed at `/usr/share/xmr-gateway/scripts/render-wallet-rpc-conf.sh` across `.deb`, `.rpm`, and release `.tar.gz` bundles, eliminating systemd's premature `${...}` environment expansion (`Invalid environment variable name evaluates to an empty string: cr%x, nl%x`) that blocked service startup in `v0.1.2`.
- **SELinux `etc_t` Context Preservation (`admin/lib/common.sh`, `admin/config.sh`, `start.sh`, `postinst`):** Atomic `.env` rewrites now create temporary files inside the target `.env`'s own directory (`$(dirname "$target")/.env.tmp.XXXXXX`), preserve ownership via `chown --reference` and `0600` mode prior to `mv`, and invoke `restorecon` when available on `/etc/xmr-gateway/.env` so SELinux `Enforcing` hosts retain `etc_t` instead of `user_tmp_t`.
- **Fail-Closed Mainnet Public HTTP Webhooks (`src/config.rs`, `admin/config.sh`, `.env.example`):** On `MONERO_NETWORK=mainnet` with `ALLOW_PRIVATE_WEBHOOKS=false`, `REQUIRE_HTTPS_WEBHOOKS` now defaults to `true` when omitted, and setting `REQUIRE_HTTPS_WEBHOOKS=false` fails closed at startup (and reports `FAIL` in `config doctor`). Cleartext HTTP remains permitted on `stagenet`/`testnet` or with `ALLOW_PRIVATE_WEBHOOKS=true` for local loopback bots.
- **Chunked `get_transfers` Scanner Batching (`src/services/scanner.rs`, `src/config.rs`):** Added `SCANNER_SUBADDRESS_BATCH_SIZE` (`1..=1000`, default `100`), grouping monitored subaddresses by `account_index` and querying `monero-wallet-rpc` in disjoint chunks to prevent exceeding the 16 MiB RPC response limit, with strict fail-closed error propagation before database writes so partial batch failures never falsely orphan or reorg invoices.
- **Per-Attempt Fresh Webhook Timestamps & Signatures (`src/services/webhook.rs`, `admin/webhooks.sh`, `demo-stagenet.sh`):** Computes fresh Unix epoch `X-Webhook-Timestamp` and `X-Webhook-Signature` (`HMAC-SHA256(WEBHOOK_SECRET, "{timestamp}.{payload}")`) on every initial delivery, exponential-backoff retry, and manual operator retry while preserving immutable `event_id` (`X-Webhook-Event-Id` / `X-Delivery-Id`) and JSON payload bytes for idempotent deduplication (retaining backwards-compatible `X-Signature-256`).
- **Security & Architecture Documentation (`README.md`, `README_RU.md`, `DEPLOY_EN.md`, `DEPLOY_RU.md`):** Clarified view-only vs. hot-wallet trust boundaries, single-instance SQLite / single-merchant deployment scope, opaque PII-free `order_id` guidance, updated webhook verification examples, and replaced imprecise wording with self-hosted technical terminology.

## [0.1.2] - 2026-11-20

### Fixed
- **POSIX `sh` Newline Guard Regression (`monero-wallet-rpc.service` & `Containerfile.monero-rpc`):** Replaced broken `$(printf "\n")` (which POSIX command substitution strips to empty string, causing `**` to reject all valid credentials) with `nl="$(printf '\nx')"; nl="${nl%x}"` (and `%%` escaped as `${nl%%x}` / `${cr%%x}` inside systemd `ExecStartPre`), restoring startup for `.rpm`/`.deb` systemd services and Docker/Podman containers.
- **System Package `service setup-rpc` Target & Permissions (`admin/service.sh`, `start.sh`):** Always targets `/usr/local/bin` (instead of `/usr/share/xmr-gateway/bin`) when running from a system package install (`/usr/share/xmr-gateway`, `/usr/lib/*`, or `/etc/xmr-gateway/.env`), and creates `$BIN_DIR` via `install -d -m 0755` so `User=xmr-gateway` can always execute `monero-wallet-rpc` under `umask 077`.
- **Unified `.rpm`/`.deb` DB & Wallet Paths (`postinst`, `common.sh`, `wallet.sh`, `config.sh`):** System package post-install now rewrites seeded `/etc/xmr-gateway/.env` to `DATABASE_URL=sqlite:///var/lib/xmr-gateway/xmr_gateway.db`, `admin/lib/common.sh` flattens legacy relative `sqlite://data/...` paths for `/etc/xmr-gateway/.env`, and `admin/wallet.sh` enforces `0700`/`0600` `xmr-gateway:xmr-gateway` ownership on `/var/lib/xmr-gateway/wallet`, eliminating the `/var/lib/xmr-gateway/data/wallet` vs `/var/lib/xmr-gateway/wallet` mismatch.
- **Network-Aware Default `WALLET_RESTORE_HEIGHT` (`.env.example`, `.env.docker.example`):** Left `WALLET_RESTORE_HEIGHT=` empty by default so `start.sh` and `admin/lib/common.sh` auto-select `3280000` (mainnet), `1600000` (stagenet), or `2600000` (testnet) instead of overriding stagenet with mainnet height `3280000`.
- **Runtime Regression Tests (`admin/test_admin.sh`):** Added real executable runtime tests that run extracted `monero-wallet-rpc.service` `ExecStartPre` and `Containerfile.monero-rpc` `entrypoint-monero-rpc.sh` through `/bin/sh` (positive + `\n`/`\r` negative cases), verify `resolve_setup_rpc_bin_dir` + `0755` `BIN_DIR` under `umask 077`, and validate `postinst` + `load_env` path/height consistency.

## [0.1.1] - 2026-11-20

### Fixed
- **systemd (`monero-wallet-rpc.service`):** Escaped all `printf` format specifiers (`%%s`) in `ExecStartPre` so `systemd` no longer substitutes `%s` with `/bin/bash`; added newline-injection guards and network-aware default `MONERO_REMOTE_NODE` resolution.
- **Release Tarball, `.deb`, and `.rpm` Packaging:** Included `start.sh` (`0755`), `CHANGELOG.md`, and all Podman Quadlet files (including `xmr-gateway-egress.network`) in release tarballs and system packages; fixed `admin/service.sh` (`service setup-rpc`) to reliably resolve `start.sh` and target `/usr/local/bin` on read-only system installs (`XMR_BIN_DIR`) with `x86_64` and `aarch64` Monero CLI SHA256 pinning.
- **Podman 5 Quadlet Networking:** Replaced conflicting `Network=pasta` alongside `xmr-gateway-internal.network` with a dedicated `deploy/podman/quadlet/xmr-gateway-egress.network` bridge in both `monero-wallet-rpc.container` and `xmr-gateway.container`.
- **Container Volume Isolation & SELinux `:Z` Safety:** Separated gateway SQLite storage from wallet key files into non-overlapping sibling directories (`~/.local/share/xmr-gateway/data:/data:Z` in Quadlet and `../../data/gateway:/data:rw` in `docker-compose.yml` / `.env.docker.example`), eliminating both wallet file exposure to `xmr-gateway` and SELinux MCS `:Z` relabel conflicts.
- **RBAC Key Rotation & `.env.example`:** Uncommented `OPERATOR_API_KEY` in `.env.example`, updated `admin/config.sh` (`config rotate-keys all`) to always generate/rotate a distinct `OPERATOR_API_KEY`, and ensured `start.sh` replaces placeholder `OPERATOR_API_KEY` values automatically.
- **Container Graceful Shutdown (`SIGTERM`):** Added explicit `StopSignal=SIGTERM` and `StopTimeout=30` (`TimeoutStopSec=40`) in Podman Quadlet container units alongside `exec /usr/local/bin/monero-wallet-rpc --non-interactive --no-initial-sync` and log-size bounds in `Containerfile.monero-rpc`.
- **Systemd Wallet Initialization (`gateway_wallet.password`):** Hardened `admin/wallet.sh` (`create-hot`, `create-view-only`) to enforce `0600` permissions and automatically restore `xmr-gateway:xmr-gateway` ownership under `/var/lib/xmr-gateway/` when invoked via `sudo`.
- **OCI `HEALTHCHECK` & Podman Warnings:** Moved gateway healthchecks out of `Containerfile` into native `healthcheck:` (`deploy/docker/docker-compose.yml`) and `HealthCmd=` / `HealthInterval=` / `HealthTimeout=` / `HealthStartPeriod=` / `HealthRetries=` (`deploy/podman/quadlet/xmr-gateway.container`), eliminating OCI build warnings.
- **Network-Aware Default `MONERO_REMOTE_NODE`:** Automatically selects appropriate public remote nodes (`mainnet`, `stagenet`, `testnet`) when `MONERO_REMOTE_NODE` is empty across `start.sh`, `admin/lib/common.sh`, `monero-wallet-rpc.service`, and `Containerfile.monero-rpc`, and warns in `config doctor` on network/node mismatches.
- **Installer & Admin UX:** Split post-install output in `scripts/install.sh` cleanly between `tarball` (`$PREFIX` + `admin.sh`) and `deb`/`rpm` (`systemd`), enabled unprivileged `--prefix "$HOME/..."` tarball installs, silenced transient `curl: (7)` connection-refused spam in `admin/service.sh` startup polling loops, and derived webhook `User-Agent` from `CARGO_PKG_VERSION`.
- **Documentation (`DEPLOY_EN.md`, `DEPLOY_RU.md`, Quadlet headers):** Corrected Quadlet activation (`systemctl --user daemon-reload && systemctl --user start ...` instead of `enable --now`) and added complete Rootless Podman + SELinux `Enforcing` (`chcon`, `podman unshare chown`, one-shot wallet init container) guides.

## [0.1.0] - 2026-11-20

### Added
- Non-custodial Monero (XMR) payment gateway core (`axum`, SQLite WAL `BEGIN IMMEDIATE`, per-invoice subaddresses, reorg-safe state machine with unlocked covering-set `SETTLED`/`COMPLETED` finality, crash-safe `sweep_all`, HMAC-SHA256 SSRF-hardened webhooks, constant-time RBAC with mandatory `OPERATOR_API_KEY` for `hot_wallet`, fail-closed `view_only` RPC verification).
- Bilingual (`EN`/`RU`) CLI & interactive admin suite (`admin.sh`, `admin/*`), native `.deb`/`.rpm`/tarball packaging, fail-closed `scripts/install.sh`, hardened `systemd` units, Docker Compose, rootless Podman Quadlet, reverse-proxy templates, and GitHub Actions CI/Security/Release pipelines.
